# Устав команды «Mein Deutsch»

Принят 6 ноября 2026, упрощён 9 ноября 2026 (Алина выбрала вариант «Автоматика вместо ритуалов»). Действует в каждом запросе проекта.

Почему упростили: после появления команды работа стала дольше, а качество не выросло. Все ошибки, которые дошли до Алины 8–9 ноября, были в поведении страницы (поле дёргается при наборе, две функции с одним именем сломали папки словарика, в одном типе заданий не было звука). Ревьюер по скриншотам такое не видит, а семь ролей по очереди — это один исполнитель с длинным чек-листом. Ошибки ловит автоматика, поэтому проверки теперь там.

## Правила

1. Польза для обучения важнее скорости и развлечения.
2. Работа строится от данных: `STATUS.md`, `build/status.json`, прогресс и ошибки в «Mein Deutsch», последние темы с репетитором (`data/modules.json`, `data/lessons.json`, доска A2).
3. Пройденные уроки не правятся. Прогресс не теряется: перед изменением данных резервная копия.
4. Не опережать репетитора: новая грамматика после её урока или с пометкой «новое, самостоятельно».
5. Стиль Mein Deutsch (цвета, шрифты, настроение) не меняется. Вкус Алины и отвергнутое — в `QUALITY.md`.
6. Крупное (новая раскладка, новый формат, удаление функции) — 2–3 варианта разной структуры с рекомендацией или одна неочевидная идея, делать после согласия. Мелкое и обратимое — делать и называть.
7. Ответ Алине: результат, ссылка или скриншот, одна строка о проверках. Без пересказа ролей и процесса.
8. Когда Алина просит быстрее, сначала выпускается то, что работает и прошло автотест, доводка потом.

## Что держать в голове (бывшие роли)

- **Содержание.** Цель урока от статусов: сначала `stuck`, потом свежие ошибки, потом `learning`. Одна-две цели. Схема: вспомнить старое → одна новая вещь → узнать → выбрать → собрать → сказать самой → короткое повторение. Каждое задание тренирует одну узкую вещь; где путаются две формы, минимальные пары. Образец структуры — уроки Deutsch mit Yehor. Урок около 5 минут, слова из жизни Алины.
- **Немецкий.** Весь немецкий текст проверяется отдельным проходом носителя: грамматика, артикли, естественность, неверные варианты точно неверны, у верного нет второго прочтения.
- **Интерфейс.** Телефон первым, без горизонтальной прокрутки, крупные зоны нажатия. Одно главное действие на экран. Новые экраны из UI-кита дизайн-системы (`design/README.md`). Иллюстрации: взрослые подробные люди, Canva, только там, где картинка учит.
- **Код.** Простые решения без лишних библиотек, данные по схемам deutsch-base. Изменение в одном типе задания переносится во все похожие типы (звук, серия, обратная связь).
- **Новые форматы.** Хотя бы один по-настоящему другой подход; идея идёт в работу, только если понятно, чему она учит. Отклонённые идеи записываются с причиной.

## Проверки перед публикацией

Шесть пунктов вместо чек-листа ролей. Первые два обязательны всегда.

1. `npm run page-check -- страница.html` — синтаксис, дубли имён, поля ввода без задержки.
2. `npm run smoke -- страница.html папка-с-уроками` — на телефоне 390 px проходит каждый урок до финала, ловит ошибки JS, ответы без звука, застрявшие этапы, незаписанный прогресс, дёргающиеся поля и лишние запросы. Как получить уроки: `ArtifactData list lessons` с `out_dir`. Если баг дошёл до Алины, в автотест добавляется проверка, которая его ловит.
3. Автор сам смотрит скриншот телефона 390 px изменённого экрана: куда падает взгляд, нет ли лишнего и отвергнутого.
4. Новый немецкий текст прошёл проверку носителя; у каждого задания ровно один верный ответ, в «найди в тексте» минимум два кандидата.
5. Новый экран, новый формат или варианты дизайна — один круг независимого ревьюера (`automation/review.md`). Для исправлений, демо и мелких правок ревьюер не нужен.
6. Изменился экран или принят макет — в тот же день обновить канвас «Макеты Mein Deutsch» (https://claude.ai/artifact/PSekVhmy4oB1DqZooREPzv): свежий снимок `npm run screens` в рамку раздела, принятый макет до переноса отдельной рамкой «переносится», расхождение запиской рядом. Порядок: `design/README.md`.
